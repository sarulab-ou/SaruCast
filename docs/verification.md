# 検証結果 — SaruCast 0.1.1

2026-11-06（日本時間）。配布物は **SaruCast-win-x64.zip**。
ZIP全体を展開して最上位のSaruCast.exeを起動する。SelfContained=true、win-x64、PublishSingleFile=false。

## 環境

Windows 11 Education x64（10.0.26200）、Intel Core Ultra 7 255H（論理16CPU）、Intel Arc 140T GPU（ドライバー32.0.101.6452）。1920×1280の単一モニター、Wi-Fi IPv4。Cast機器名は「オフィス」。メーカー・機種は確認できておらず推定しない。

.NET SDK 10.0.403、同梱ランタイム10.0.14、FFmpeg 9.0.2最小構成、NAudio 2.2.1。

## 実施結果

| 項目 | 確認した範囲 |
|---|---|
| ビルド・テスト | Cast/DNS/HTTP、WPF終了イベント、繰り返し終了処理を含む28項目が成功 |
| 発見・接続 | 実機「オフィス」をmDNSで発見しCast応答を確認 |
| 実機の映像と音 | 利用者がテスト映像の表示を確認。音声はいったん確認を留保した後、PCでは発音しない専用テストで「テレビから音が聞こえる」と再確認 |
| 実機へのデータ送信 | プレイリスト・TSセグメント取得とPLAYINGを記録。テストパターンでは再生開始後60秒、終了時までPLAYINGを確認 |
| 実デスクトップ | DXGI＋WASAPI＋GPU H.264/AACで配信。読み取り時刻の上書きを除いた最終方式で再生開始後20秒、PLAYINGを維持。個々の画面内容をテレビで撮影確認してはいない |
| PC再生音声 | WASAPI入力が非無音（PCM16 peak 29204）。別途PCテスト音の取得も確認 |
| 音声データ | AAC-LC、48kHz、2chを確認。配信テスト音をAACからPCMへ復号しpeak 2902で無音ではないことを検査 |
| 映像 | H.264/30fps、1620×1080と1080×720で縦横比を維持。復号フレームが全面黒でないことを検査 |
| ソフトウェア方式 | 初期版でDXGI＋ソフトウェアH.264＋WASAPIを10秒確認。最終方式の長時間実機試験は未実施 |
| 終了 | Cast STOP、HTTP endpoint閉鎖、FFmpeg終了、一時セッション削除。WPFの実Closingイベントを表示しない専用ウィンドウで発火し、接続前の終了と終了連打を回帰検証 |
| 配布の構成 | 0.1.1 ZIPを空白入りパスへ全展開し、同梱ファイルのハッシュと製品バージョン0.1.1を検査。外部DOTNET_ROOTを無効化・PATHから開発ツールを除いて起動し、同梱FFmpegによる720pの実画面＋WASAPI取得8秒と復号検査も成功。終了後に診断用プロセス・セッションなし |

模擬Receiverと実機の成功は区別する。自動診断JSONのtelevisionPlaybackVerified=falseは、プログラム自身がテレビ表示を目視できないことを表す。上表の現物確認はこのセッションの利用者報告に基づく。

## 測定値

| 条件 | 結果 |
|---|---|
| 720pテストパターン＋合成音、実機60秒 | エンコーダー準備6.25秒、PLAYINGまで10.67秒、セグメント取得68回 |
| 同試験のFFmpeg | CPU平均1.61%、Working Set 167.0→166.2 MB |
| 同試験のSaruCast | Working Set 61.6→64.5 MB |
| 720p実画面＋WASAPI、最終時刻方式20秒 | 準備6.54秒、PLAYINGまで11.46秒。FFmpeg CPU平均9.13%、Working Set 272.7→300.8 MB |

CPUは区間のFFmpeg CPU時間差を経過時間と16論理CPUで割った全体比率。メモリは開始・終了の2点であり、リークや長期安定性の証明にはならない。PLAYINGまでの時間はテレビ表示遅延ではない。

目標ビットレートは1080pで6Mbps、720pで3Mbps、音声160kbps。実際の値は映像の内容で変わる。テレビ表示までの遅延は未実測。

## 修正内容

- Cast接続後のIPv6マップ形式アドレスでHTTP bindを失敗する経路を、IPv4ソケットの明示で修正。
- HLS送信値を音声ts・映像mpeg2_tsへ修正。Receiverの初期IDLEを終了と区別し、要求したコンテンツだけを追跡。
- 初期セグメントと保持数を増やして開始位置を明示。DXGIの取得時刻とPCMサンプル時刻を、読み取り時刻で上書きする方式を除去。
- Closingイベント内での再Closeを非同期化。停止の完了を共有し、一部の後始末に失敗しても残りの資源を解放。
- 手入力IPの保存・復元、検索と接続確認の競合、古い接続からの状態上書きを修正。

## 未検証・未達

- 開発ツール・ランタイムを一度も入れていない別のクリーンなWindows 11 x64での起動。
- 30分の実機連続配信、音ずれの実測、長期メモリ増加、PCとテレビのカウンター同時撮影による表示遅延。
- Chrome完全終了時と、GPUアクセラレーションONのスクロール・非保護動画について、テレビ表示を個別に確認する受け入れ試験。
- 音声OFF、開始キャンセル、再接続、TV電源OFF、スリープ復帰、音声出力先変更を含む最終GUIの網羅的な実機操作。
- 複数モニター、複数NIC、VPN、有線併用、別機種テレビ。今回の検証は各1系統。
- WGC、HDR変換、個別ウィンドウ共有、直接Cast Streaming、1秒未満の表示遅延。
- Cast device-auth証明書検証。自己署名TLSを許容するため、信頼できるLANで使うテスト版。
- Authenticode署名。使用可能な証明書を確認できず未署名。

生の診断結果は開発フォルダーartifacts/のJSON・ログに保存。LANアドレスやセッションURLを含む診断データは配布ZIPに追加しない。
